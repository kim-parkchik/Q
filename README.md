<h1 align="center">Q (Q Payroll)</h1>

<p align="center">
  <strong>「給与計算を、もっと自由に。もっとパーソナルに。」</strong><br>
  ローカル環境で完結する、軽量・高速な給与計算ソフト。
</p>

---

Q は、日本の小規模な会社・個人事業主のための給与計算ソフトです。
勤怠の入力から、残業代・社会保険料・源泉所得税の計算、給与明細の印刷までを、自分のPC1台で行えます。
会社のデータはクラウドではなく、手元のファイル（.qp）に保存します。

> [!NOTE]
> 開発中です。配布用のファイル（インストーラー）はまだありません。
> 計算結果は、実務で使う前に必ずご自身で確かめてください。

- [x] 時間外（1日8時間・週40時間を超えた分）・深夜・法定休日の割増

- [x] 月60時間超の割増50%（中小企業は、2023年3月までに働いた分を25%で計算）

- [x] 残業代の対象外（管理監督者など、労働基準法41条の人と役員）：時間外・休日労働の手当を払わず、深夜の割増賃金だけ払う

- [x] 固定残業代の時間の目安（従業員画面）：固定残業代が時間外労働の何時間分に当たるかと、設定した時間分の割増賃金を、給与計算と同じ残業代の時給（（基本給 ＋ 残業代の時給に入れる手当）÷ 月平均所定労働時間。25%増し、月60時間超は50%増し）で出し、足りなければ知らせる
- [x] 健康保険・介護保険（40〜64歳かどうかを生年月日で判定）・厚生年金（協会けんぽ・全47都道府県）

- [x] 社会保険料は、入社した月の分から、退職日の翌日（資格喪失日）がある月の前月分まで引く（月末退職・入社した月の退職にも対応）
- [x] 社会保険料の徴収月（当月徴収・翌月徴収）を給与規定グループごとに選べる。翌月徴収では、前月の分の料率・標準報酬月額・入社月・退職月・産休育休の免除で計算し、月末に退職する人の最後の給与からは2か月分を引ける（健康保険法167条・厚生年金保険法84条）
- [x] 計算期間の途中で入社・退職した月給制の人の日割り（給与規定グループごとに、日割りしない・所定労働日数・暦日数から選ぶ。月給と「固定」の支給項目を日割りし、1円未満は切り上げ。所定労働日数は会社カレンダーから数える）
- [x] 標準報酬月額の履歴（何年何月分から・いくら・理由）。過去の月も、その月の分の標準報酬月額で計算する
- [x] 基本給（給与区分・金額）・扶養人数の履歴（何年何月分から）。給与・賞与・算定基礎は、その月の分の値で計算する（時給制・日給制は勤怠を確定した日の時給・日給で計算し、履歴と違えば給与明細で知らせる）
- [x] 算定基礎（定時決定）：確定した4〜6月の給与と支払基礎日数から9月分からの標準報酬月額を計算し、履歴に登録する（17日・短時間就労者の15日・短時間労働者の11日、途中入社の月の除外に対応）
- [x] 年間報酬の平均による保険者算定（定時決定）：前年7月〜当年6月の平均と4〜6月の平均に2等級以上の差がある人を出し、申し立てる人は年間平均で決めた額を登録できる（上限・下限の1等級差の特例に対応。例年の差かと本人の同意は画面で選ぶ）

- [x] 申告書の内容（本人・配偶者・扶養親族・保険料・住宅借入金等特別控除・前の勤め先の給与）を入れると、確定した1年分の給与・賞与から年税額と過不足額を出す（扶養親族の区分は12月31日の年齢と所得で自動で決める）
- [x] 過不足額の精算：12月（または翌年1月）に支払う給与の明細に還付・徴収を載せ、差引支給額で精算する（12月の給与の税額計算を省略しない方法）
- [x] 給与所得の源泉徴収票（受給者交付用）の印刷・PDF保存：年末調整をした人は保存した申告書の内容から、年の途中で退職した人・乙欄・丙欄の人は確定した給与・賞与の合計から作る（書き方は国税庁「法定調書の作成と提出の手引」。区分の数字は PDF から自動で読み取り、手引の記載例と一致することを確認済み）

- [x] 乙欄の人の源泉徴収票・給与支払報告書の「従たる給与」の欄：年末調整の画面で従たる給与についての扶養控除等申告書の内容（配偶者・扶養親族）を入れると、「従有」と人数の「従」の欄、氏名の欄に書く（16歳未満・障害者・本人の欄は書かない。所得税法195条）。乙欄の税額に使う扶養人数と申告書の人数が違えば知らせる

- [x] 給与支払報告書の eLTAX 用の CSV（総務省通知形式。146項目の並びは地方税共同機構の仕様書の Excel から自動生成）：出す人を1つのファイルにまとめて書き出し、PCdesk の「CSV 取込による作成」で取り込める。文字の属性・文字数・使えない文字を確かめ、直すところがある人は理由を出して入れない。マイナンバーは、事務取扱担当者が書き出したときだけ書く
- [x] 紙の給与支払報告書：市区町村ごとに総括表（地方税法施行規則 第十七号様式）と、出す人ごとの個人別明細書（同別表）を A5 で印刷する。報告人員・受給者総人員・給与の支払期間は自動で数え、会社の表にない事項（事業種目・所轄税務署・連絡者など）は画面で入れておく。マイナンバーは事務取扱担当者が印刷するときだけ書き、記録に残す。出す期限は土日・祝日なら次の日にして出す
- [x] マイナンバー：本人と家族（年末調整の申告書に入れた配偶者・扶養親族）の番号を登録する（12桁目の検査用数字を総務省令の算式で確かめる。家族は氏名と生年月日で年をまたいで同じ人とみなす）。扱えるのは、システム設定で「事務取扱担当者」の印を付けたユーザーだけ。番号はふだん隠し、表示・登録・直す・消す・CSV の書き出しを記録に残す（記録に番号は書かない）
- [x] マイナンバーの暗号化：はじめに事務取扱担当者がパスワード（15文字以上）を決め、番号を AES-256-GCM で暗号化して置く。鍵はパスワードから Argon2id で作り、回復用キー（52文字。1回だけ出して印刷・書き写してもらう）でも開けられる。使うときに鍵を開け、使わなくなってから15分で自動で閉じる。パスワードの変更・回復用キーの作り直し・回復用キーで開けて決め直すことができ、鍵の開け閉めも記録に残す

### まだできないこと（今後の予定）

## 計算の正確さについて
給与計算ソフトでいちばん怖いのは、もっともらしく見えて間違っている数字です。Q では次のことを守っています。

- **料率や税額を、手やAIで書き写さない。** 公式のファイルから、スクリプト（[scripts/](scripts/)）で機械的に読み取ってデータを作っています。
  - 協会けんぽの保険料額表（Excel）：読み取った料率で計算した保険料が、Excel に印刷された全額・折半額と、全47都道府県・全50等級で一致することを確かめています。1つでも合わなければ、データを作らずに止まります。
  - 国税庁の源泉徴収税額表（月額表、日額表の丙欄、賞与に対する源泉徴収税額の算出率の表。Excel）
  - 厚生労働省の雇用保険料率（PDF）
- **データには出典のURLを残す。** 元のファイルは [insurance-tables/](insurance-tables/)・[tax-tables/](tax-tables/)・[minimum-wage-tables/](minimum-wage-tables/)・[nencho-tables/](nencho-tables/) に置いてあり（年末調整の PDF は大きいので、入手元とハッシュだけ）、新しい年度の追加手順もそこに書いています。
- **自動テスト**（`bun test`）で、計算結果を確かめています。

### 計算できる期間

| 種類 | 登録している期間 |
|---|---|
| 健康保険・介護保険・厚生年金（協会けんぽ） | 2020年3月分〜2027年2月分 |
| 雇用保険 | 2020年4月分〜2027年3月分 |
| 子ども・子育て支援金 | 2026年4月分から |
| 源泉所得税 | 2020年〜2026年に支払う給与・賞与 |
| 定額減税 | 令和6年分（2024年） |
| 最低賃金のチェック | 令和3年度〜令和8年度（2021年10月ごろの発効日から） |

料率は「何年何月分から」で切り替わるので、年度の途中の改定（令和2年9月の厚生年金の上限、令和4年10月の雇用保険料率など）も、その月から反映されます。
登録していない月を計算したときは、いちばん近い料率で計算し、画面に注意を出します。
2020年3月分より前を登録していない理由は、[insurance-tables/README.md](insurance-tables/README.md) に書いています。

## プロジェクト名について
本プロジェクトは「はま給与（hama-kyuyo）」としてスタートしましたが、現在は **「Q」** という名称で開発を進めています。

- **由来**: 給与の「給（きゅう）ちゃん」から。
- **コンセプト**: 
  - **Quick**: ローカル動作ならではの素早さ
  - **Quality**: 確かな計算精度
  - **Quest**: 理想の給与計算環境の追求
  
（当初は「給ちゃん」という愛称を検討していましたが、親しみやすさを残しつつ、よりシンプルでプロ向けの道具感を出すために一文字の「Q」に決定しました。）

## 開発の背景
市場の給与計算ソフトがクラウド・サブスク型に偏る中、個人事業主や小規模事業者、そして若いアントレプレナーにとって、データの自己管理とランニングコストの削減は重要な課題です。
外部サービスに依存せず、自分のPC一台で完結する、シンプルでコントロール可能な給与計算環境を目指し、本ツールを自作しています。

## 開発の目的
- 「自分が作った」と言える成果物をひとつ完成させること
- クラウドに依存しない、安全で自由な給与計算環境の提供

## プロジェクトの特色：AIとの共創
本プロジェクトは、実務家（非プログラマ）が生成AIを「技術アドバイザー」としてフル活用し、設計から実装までを行う**「AI共創型開発」**の実践です。

- **実務知とITの融合**: 給与計算の実務知識を軸に、生成AIの技術支援を受けることで、専門外であったモダンな技術スタックでの開発を実現。
- **文系AI活用の実践**: 既存のソフトを「消費」するだけでなく、生成AIをパートナーに「作る側」へ回ることで、給与計算ロジックの透明性と自由度を自らの手に取り戻す試みです。

## 技術スタック
ローカルでの動作を前提に、AIとの対話を通じて選定した構成です。

- **Runtime**: [Bun](https://bun.sh/) (高速な実行環境)
- **Framework**: [Tauri](https://tauri.app/) (デスクトップアプリ化)
- **Frontend**: React + TypeScript (UI構築)
- **Icons**: Lucide React (軽量で一貫性のあるアイコンライブラリ)
- **Database**: SQLite (ローカルデータ保存)

## データの保存について
会社ごとのデータを、.qp（Q Payroll のメインファイル）という独自の拡張子のファイルで管理しています。

- **メインデータ（.qp）**: 通常の業務で使用する、読み書きできるファイルです。
- **バックアップデータ（.qb）**: 自動で作られるバックアップファイルです。
- **ポータビリティ**: データのバックアップや PC 間での受け渡しを「1つのファイル」として容易に行えます。

会社・従業員のデータを、外部のサーバーに保存することはありません。
インターネットを使うのは、祝日の取り込み（内閣府のCSV）、法人番号からの会社情報の検索（国税庁）、郵便番号からの住所の検索のときだけです。

## 今後の展望：スタンドアロン・アプリへの展開
本プロジェクトは、最終的に **「インストーラーや.exeファイルをダブルクリックするだけで、誰でもすぐに使い始められるデスクトップアプリ」** として配布・運用することを目指しています。

- **環境構築不要**: コマンド操作（Bunのインストール等）を必要とせず、一般的なソフトと同様の直感的な導入を実現します。
- **完全ローカル完結**: ネット環境に依存せず、PCを開けば即座に業務を開始できる「究極の道具感」を追求します。
- **ファイルから開く**: .qp ファイルをダブルクリックするだけで、その会社のデータを開ける操作を実現します。バックアップ（.qb）は、いまはアプリの「開く」で選ぶと、写しの会社ファイル（.qp）を作って開きます（バックアップのファイルは変えません）。

## 動作環境について
本プロジェクトは、macOS 環境での開発・検証を行っています。
Windows / Linux 環境での動作確認は行っていません。

## 開発用に動かす
1. [Bun](https://bun.sh/) と、Tauri に必要なもの（Rust など。[Tauri の案内](https://tauri.app/start/prerequisites/)）を入れておく

2. 依存関係のインストール
   ```bash
   bun install
   ```

3. 開発モードで起動
   ```bash
   bun tauri dev
   ```

4. 自動テストの実行
   ```bash
   bun test
   ```
