<h1 align="center">Q (Q Payroll)</h1>

<p align="center">
  <strong>「給与計算を、もっと自由に。もっとパーソナルに。」</strong><br>
  ローカル環境で完結する、軽量・高速な給与計算ソフト。
</p>

---

Q は、日本の小規模な会社・個人事業主のための給与計算ソフトです。
勤怠の入力から、残業代・社会保険料・源泉所得税の計算、給与明細の印刷までを、自分のPC1台で行えます。
会社のデータはクラウドではなく、手元のファイル（.qp）に保存します。

> [!NOTE]
> 開発中です。配布用のファイル（インストーラー）はまだありません。
> 計算結果は、実務で使う前に必ずご自身で確かめてください。

## できること

### 会社・従業員

- [x] バックアップ（.qb）を開くときは、バックアップのファイルを変えないように、写しの会社ファイル（.qp）を作って開く
- [x] 賞与の確定など、いくつかの書き込みをまとめて行うときは、1つのトランザクションで保存する（途中で失敗したら全部取り消す。Rust 側の execute_batch）
- [x] ログインと、複数ユーザーの登録
- [x] 拠点（支店）ごとの都道府県（協会けんぽの料率は、拠点の都道府県で決まる。わからないときは、ほかの都道府県で仮に計算せず、健康保険料・介護保険料を計算しないで画面で知らせ、給与・賞与を確定できないようにする）
- [x] 給与規定グループ（締日・支払日）と、端数処理の設定（社会保険料・雇用保険料の初めの値は、給与から引くときの原則の「50銭以下切り捨て・50銭超切り上げ」。残業代・深夜手当などは、時間外・休日・深夜の手当ごとに1か月の合計で端数を処理し、給与明細の行を足すと支給合計になる）
- [x] 手当・控除の項目の追加
- [x] 法人番号のチェックと、法人番号からの会社情報の検索
- [x] 中小企業かどうかの設定（月60時間超の割増の猶予に使う）

### 勤怠
- [x] 会社カレンダー（祝日の取り込み、休日・法定休日の設定）
- [x] 日ごとの出退勤の入力と確定（給与を確定した人・月の勤怠は変えられない。直すときは、給与明細で「確定を取り消す」をしてから直し、確定し直す）
- [x] 勤怠データのCSV出力・取り込み
- [x] 休憩を1日に何回でも入れられる（勤怠の表には1回目を出し、2回目からは「休憩の一覧」の画面で入れる。私用の外出・中抜けも休憩として入れる。TimeQard の休憩の打刻・休憩の申し出（始めと終わり）も取り込める）
- [x] 決まった休憩（休憩を打刻しない会社など）：給与規定グループごとに、「12:00〜13:00」のように時刻で、または「6時間を超えたら45分、8時間を超えたら60分」のように長さで決め、勤怠を確定するときに引く。打刻・手入力した休憩がある日の合わせ方は選べる（打刻を優先・合わせて引く（重なるところは1つにまとめる）・長いほう・合算）。休憩を取らなかった日は「休憩なし」に印を付ける（TimeQard の「休憩を取れなかった」の申し出を取り込んで、選んだ日を「休憩なし」にすることもできる）。時刻で決めたときは、途中で出勤・退勤した日や時間有給にした中抜けと重なる日は引かずに知らせ、長さで決めたときは深夜の時間をできるだけ減らさない（働いた時間・深夜の割増を少なく数えないため）。従業員ごとに使わないようにもできる。休憩が労働基準法34条の長さ（労働時間6時間超で45分、8時間超で1時間）より短い日を知らせる
- [x] 時間単位の有給（会社の設定で使う・使わないを決める。労使協定を結んだとき）：中抜けに「時間有給」の印を付けると、働いた時間にも休憩にも入れず、時間有給（1時間単位）で有給として数える。1年（付与日から1年）に5日分を超えたら知らせる（労働基準法39条4項）
- [x] 半日単位の有給（半休）：会社の設定で使う・使わないを決める（初めは使う）。年次有給休暇は1日単位が原則で、半日単位は本人が希望し会社が同意したときに取れるもの（厚生労働省。労使協定・日数の上限はいらない）。使わない会社では、勤怠の区分に「半休(有給)」を出さず、前に入れた半休があれば知らせる。半日は、1日の所定労働時間の半分として計算する
- [x] 遅刻・早退・中抜けの控除（月給制・日給制。給与規定グループで選ぶ。初めは引かない）：出勤・半休の日に、働いた時間と時間有給を合わせても所定労働時間に足りない時間の分を、1か月平均所定労働時間か計算期間の所定労働時間で割って月給から引く（日給制は 日給 ÷ 1日の所定労働時間）。給与明細に計算式を出す
- [x] フレックスタイム制（清算期間は給与の計算期間の1・2・3か月。月給制・日給制・時給制）：従業員の画面で「フレックスタイム制を適用」にした人は、1日8時間・週40時間では残業を数えず、清算期間の合計で清算する。実労働（法定休日の労働を除く）が法定の総枠（40時間 × 暦日数 ÷ 7。0.1時間未満は切り捨てて、厚生労働省の手引きの表と同じにする。完全週休2日の会社は、労使協定で「所定労働日数 × 8時間」にできる）を超えた時間が時間外労働（25%増。月60時間を超えたら50%増）、総労働時間を超えて総枠までの時間は法定内（1.0倍）。清算期間（長さと起算の月）・総労働時間（所定労働日数 × 1日の所定労働時間か、1か月あたりの決めた時間）・法定の総枠・足りない時間の扱い（清算期間の終わりに引くか、次の清算期間に繰り越す。繰り越すのは法定の総枠と総労働時間の差まで。退職する月は引く）は給与規定グループで決める。清算期間が2・3か月なら、各月に週平均50時間（50時間 × 暦日数 ÷ 7）を超えた時間を、その月の時間外労働として払い、最後の月に、清算期間を通じて法定の総枠を超えた時間（各月で払った時間を除く）と総労働時間との過不足を清算する（各月の記録を確定した給与に残し、最後の月は前の月を確定してから確定する）。清算期間の途中で入社・退職した人は、働いた期間で清算する（労働基準法32条の3の2。退職する人は退職する月に清算）。月給制は、足りない時間を月給 ÷ 1か月平均所定労働時間 × 時間で引く。日給制は、日給を払った日数 × 1日の所定労働時間（と有給の時間）と比べ、超えた・足りない時間を 日給 ÷ 1日の所定労働時間 で清算する（欠勤の日は日給を払わないので、足りない時間にしない）。時給制は働いた時間の分を払い、割増分だけを足す。年休の日は、総労働時間に足りているかを見るときだけ所定の時間働いたものとして数える。欠勤・遅刻早退は別に引かず、足りない時間に入る。勤怠の画面と給与明細に清算の内訳（途中の月は、その月の実労働と週平均50時間を超えた時間）を出す（労働基準法32条の3）
- [x] 年次有給休暇の付与と残り（有給を取った日は、勤怠で確定した「全休(有給)」「半休(有給)」「時間有給」から数え、給与の計算と同じ記録を使う。期限の早い付与から引き、付与日から2年の有効期限を過ぎた分は、残りから外して「期限で消えた」日数に出す（労働基準法115条）。時間単位の有給は、1日の所定労働時間を1時間に満たない端数を切り上げた時間を1日として数える（労働基準法施行規則24条の4）。残りが足りない日は、有給休暇管理と勤怠の画面で知らせる。付与は、下の付与日の知らせから登録するか、手で登録する）
- [x] 年次有給休暇の付与日の知らせと、年5日の取得の確かめ：付与日（入社日ごと（入社6か月後、その後1年ごと）か、会社で決めた日にそろえる（統一基準日。初回は入社6か月後で2回目から決めた日か、6か月後より先に決めた日が来ればその日に初回。どちらも法定の基準日より遅くしない）。会社設定の「休暇の種類」で選ぶ）が来て、まだ登録していない付与を、有給休暇管理の画面で、日数（労働基準法39条の表。週30時間未満で週4日以下（会社カレンダーの人は1年216日以下）の人は比例付与の表。どちらも e-Gov の条文データからスクリプトで作り、比例付与の日数が「通常の日数 × 週の日数 ÷ 5.2」と合うことを確かめた）と、確定した勤怠から数えた出勤率（8割以上。年休・特別休暇の日と、産休・育休・介護休業・業務上の負傷や疾病による休業の期間は出勤とみなし、そろえて前倒しした期間も出勤とみなす。私傷病の休職などの「その他の休職」の日は、会社設定の「休暇の種類」で、全労働日から除く（初めの値）か欠勤と同じに数えるかを選ぶ。勤怠がない日があれば「確かめられない」）と一緒に知らせ、付与する・付与しない（8割未満）を選ぶ。年10日以上付与した人には、付与日から1年に年休を5日（全休1日・半休0.5日。時間単位と特別休暇は数えない）取れているかを、有給休暇管理と勤怠の画面で知らせる（労働基準法39条7項）。付与日をそろえて1年の期間が重なるときは、重なった期間をまとめて、その長さに応じた日数（月数 ÷ 12 × 5。例：18か月なら7.5日。法令に端数の決まりがないので、半日単位（半休を使わない会社は1日単位）に切り上げる。労働基準法施行規則24条の5第2項。一般的なクラウド型の勤怠ソフトと同じく、重なれば自動でまとめる）にし、10日を分けて付与したときは、合わせて10日になった日から1年で数える（はじめに分けて付与した日からの取得も数える。同4項）
- [x] 夏季休暇などの会社独自の休暇（特別休暇）と、子の看護等休暇・介護休暇：会社設定の「休暇の種類」で、種類ごとに有給か無給か・残りを数えるか（慶弔休暇のように、そのつど取る休暇は数えない）・半日でも取れるか・時間単位でも取れるか・発生（毎年◯月◯日に◯日）・消滅（付与日から◯か月か、◯月◯日まで）を決める。子の看護等休暇・介護休暇は見本から作れる（無給・毎年4月1日に5日・3月31日まで・時間単位でも取れる。2人以上で10日の人は付与の日数を直す）。時間単位の休暇は、勤怠の「時間休」に休暇の種類と時間を入れる（中抜けは休憩の一覧で休暇の印を付ける）。1日分は1日の所定労働時間（1時間に満たない端数は切り上げ）で数え、時間単位で取れるのは1日の所定労働時間に満たない時間（育児・介護休業法施行規則34条・40条）。発生の日が来たら「有給休暇管理」の画面で知らせ、ボタンで、その日に在籍している人に付与する（人ごとに付与しないこともできる）。取った日は勤怠の区分で休暇を選んで入れ、期限の早い付与から引いて残りと期限で消えた日数を出す（残りが足りない日は、有給休暇管理と勤怠の画面で知らせる）。給与：有給の休暇は、月給の人は引かず、日給・時給の人には休んだ時間（1日は所定労働時間）の分を払う。無給の休暇は、月給の人は1日・半日は欠勤控除と同じ計算、時間単位は遅刻・早退・中抜けの控除と同じ計算で引き（明細では「無給休暇控除」として欠勤・遅刻早退と分ける）、日給・時給の人には払わない。算定基礎届・月額変更届の支払基礎日数にも入れる。年次有給休暇の年5日の取得義務には数えない。会社が一斉に休む日（夏季休業など）を就業規則で休日にしているときは、会社カレンダーで休日にする

### 給与
- [x] 月給制・日給制・時給制（日給制は、所定労働日に働いた日数分の日給を払い、所定を超えた時間・休日の労働を 日給 ÷ 1日の所定労働時間 で計算した時給で払う。有給休暇は日給で払う）
- [x] 時間外（1日8時間・週40時間を超えた分）・深夜・法定休日の割増
- [x] 週40時間の数え方：週の起算曜日（会社設定）から7日で数え、計算期間の初めの日がある週は、前の計算期間の日の確定した勤怠も合わせて数える（その日の分は払わない）。所定労働時間の中の時間外労働（所定休日の出勤が週の途中にあって40時間を超えた、週の後のほうの所定労働日の時間など）は、通常の賃金を月給・日給で払っているので、割増分（25%・月60時間超は50%）だけを払う（同じ時間に通常の賃金を2回払わない）。会社カレンダーで休みの日を「出勤」で入れて働いた日は、給与明細で知らせる（「出勤」は所定労働日として計算するため。所定休日の出勤なら「所定休日出勤」にする）
- [x] 月60時間超の割増50%（中小企業は、2023年3月までに働いた分を25%で計算）
- [x] 残業代の時給：月給と手当を「1年間における1か月平均所定労働時間」（会社カレンダーから数えた1年間の所定労働日数 × 1日の所定労働時間 ÷ 12）で割る。手当は給与項目ごとに「残業代の時給に入れる」を選ぶ（家族手当・通勤手当・住宅手当などは外せる）。時給制の人の月額の手当も時間あたりにして割増に足す
- [x] 残業代の対象外（管理監督者など、労働基準法41条の人と役員）：時間外・休日労働の手当を払わず、深夜の割増賃金だけ払う
- [x] 固定残業代（月給制）：時間外労働の割増賃金に当てる定額を毎月払い、実際の時間外労働の割増賃金が上回った月は差額を「超過分」として足す（法定内残業・休日・深夜の手当は別に払う）
- [x] 固定残業代の時間の目安（従業員画面）：固定残業代が時間外労働の何時間分に当たるかと、設定した時間分の割増賃金を、給与計算と同じ残業代の時給（（基本給 ＋ 残業代の時給に入れる手当）÷ 月平均所定労働時間。25%増し、月60時間超は50%増し）で出し、足りなければ知らせる
- [x] 健康保険・介護保険（40〜64歳かどうかを生年月日で判定）・厚生年金（協会けんぽ・全47都道府県）
- [x] 健康保険組合・国民健康保険組合の人の保険料（会社設定の「社会保険規定」で足し、従業員の画面で人ごとに選ぶ。クラウド型の給与ソフトと同じ形）：健康保険組合は、組合から知らされた本人負担の料率（健康保険・介護保険・子ども・子育て支援金。組合は規約で会社の負担を半分より多くできるので、全体の料率ではなく本人負担の%。健康保険法162条）を「何年何月分から」と一緒に入れ、保険料の月の分の料率で給与・賞与を計算する（翌月徴収なら前の月の分の料率。入れていない月は計算せず、知らせて確定できないようにする）。国民健康保険組合（建設国保など）の人は、健康保険料・介護保険料・子ども・子育て支援金をかけず、国保組合の保険料（家族の人数などで決まる額）を従業員ごとの月額で毎月の給与から引き（賞与からは引かない）、所得税の計算でも社会保険料として引く。厚生年金は、どの規定の人も全国で同じ料率
- [x] 70歳に達した月の分から厚生年金を、75歳の誕生月の分から健康保険（後期高齢者医療制度へ移るため）を、生年月日で自動的に外す
- [x] 社会保険料は、入社した月の分から、退職日の翌日（資格喪失日）がある月の前月分まで引く（月末退職・入社した月の退職にも対応）
- [x] 社会保険料の徴収月（当月徴収・翌月徴収）を給与規定グループごとに選べる。翌月徴収では、前月の分の料率・標準報酬月額・入社月・退職月・産休育休の免除で計算し、月末に退職する人の最後の給与からは2か月分を引ける（健康保険法167条・厚生年金保険法84条）
- [x] 計算期間の途中で入社・退職した月給制の人の日割り（給与規定グループごとに、日割りしない・所定労働日数・暦日数から選ぶ。月給と「固定」の支給項目を日割りし、1円未満は切り上げ。所定労働日数は会社カレンダーから数える）
- [x] 月給制の人の欠勤控除（給与規定グループごとに、計算期間の所定労働日数で割る・1年間の月平均の所定労働日数で割る・しない（完全月給制）から選ぶ。所定労働日数は会社カレンダーから数え、1円未満は切り捨て、引く額は基本給まで）。欠勤控除をした月の算定・月変の支払基礎日数は、確定したときの計算期間の所定労働日数 − 欠勤日数（完全月給制は暦日数）
- [x] 標準報酬月額の履歴（何年何月分から・いくら・理由）。過去の月も、その月の分の標準報酬月額で計算する

- [x] 給与支払報告書の準備：その年に給与・賞与を支払った人を、出す先の市区町村（1月1日の住所。年の途中で退職した人は退職した日の住所）ごとにまとめる。30万円以下の退職者は出さなくてよいことを示す。市区町村ごとの指定番号と、普通徴収にする人の理由（普A〜普F。退職した人は普F、乙欄の人は普B が初めの値）を入れられる
- [x] 給与支払報告書の eLTAX 用の CSV（総務省通知形式。146項目の並びは地方税共同機構の仕様書の Excel から自動生成）：出す人を1つのファイルにまとめて書き出し、PCdesk の「CSV 取込による作成」で取り込める。文字の属性・文字数・使えない文字を確かめ、直すところがある人は理由を出して入れない。マイナンバーは、事務取扱担当者が書き出したときだけ書く
- [x] 紙の給与支払報告書：市区町村ごとに総括表（地方税法施行規則 第十七号様式）と、出す人ごとの個人別明細書（同別表）を A5 で印刷する。報告人員・受給者総人員・給与の支払期間は自動で数え、会社の表にない事項（事業種目・所轄税務署・連絡者など）は画面で入れておく。マイナンバーは事務取扱担当者が印刷するときだけ書き、記録に残す。出す期限は土日・祝日なら次の日にして出す
- [x] マイナンバー：本人と家族（年末調整の申告書に入れた配偶者・扶養親族）の番号を登録する（12桁目の検査用数字を総務省令の算式で確かめる。家族は氏名と生年月日で年をまたいで同じ人とみなす）。扱えるのは、システム設定で「事務取扱担当者」の印を付けたユーザーだけ。番号はふだん隠し、表示・登録・直す・消す・CSV の書き出しを記録に残す（記録に番号は書かない）
- [x] マイナンバーの暗号化：はじめに事務取扱担当者がパスワード（15文字以上）を決め、番号を AES-256-GCM で暗号化して置く。鍵はパスワードから Argon2id で作り、回復用キー（52文字。1回だけ出して印刷・書き写してもらう）でも開けられる。使うときに鍵を開け、使わなくなってから15分で自動で閉じる。パスワードの変更・回復用キーの作り直し・回復用キーで開けて決め直すことができ、鍵の開け閉めも記録に残す。暗号化を始める前に作ったバックアップ（暗号化していない番号が入っている）は、マイナンバーの画面に出し、確かめてから消せる
- [x] 保存期間が過ぎたマイナンバーの知らせ：要らなくなり、法令の保存期間が過ぎた番号は、できるだけ速やかに消す（個人情報保護委員会「特定個人情報の適正な取扱いに関するガイドライン（事業者編）」）。いちばん長い保存期間の扶養控除等申告書（提出期限の年の翌年1月10日の翌日から7年。所得税法施行規則76条の3）で数える（雇用保険・社会保険の書類より長い）。本人は、在籍している間（休職中も）は保管し、退職した人は最後に出した申告書の年（退職した年・最後に給与か賞与を払った年・年末調整の申告書の年のいちばん遅い年）の保存期間が過ぎたら（例：2026年に退職 → 2034年1月10日まで保管）。家族は、最後に載った申告書の年で数える（扶養から外れて7年が過ぎた家族も）。一般的な給与ソフトと同じく（よく使われている給与ソフトでは、退職者の番号を「要削除」と出す）、事務取扱担当者には、メニューの「マイナンバー」に「要削除」の数を出し、会社ファイルを開いたときに知らせる。マイナンバーの画面では、保存期間が過ぎた番号の一覧（保管する日・どの申告書の保存期間か）を出し、確かめてからまとめて消せる（1件ずつ、何の保存期間が過ぎたかを記録に残す。記録に番号は書かない。鍵は開けなくてよい）。登録してある番号ごとに「保管：◯年◯月◯日まで」も出す。退職日が入っていない「退職」の人や、在籍している人の申告書に見当たらない家族の番号は、保存期間がわからないので知らせる

## 計算の正確さについて
給与計算ソフトでいちばん怖いのは、もっともらしく見えて間違っている数字です。Q では次のことを守っています。

- **料率や税額を、手やAIで書き写さない。** 公式のファイルから、スクリプト（[scripts/](scripts/)）で機械的に読み取ってデータを作っています。
  - 協会けんぽの保険料額表（Excel）：読み取った料率で計算した保険料が、Excel に印刷された全額・折半額と、全47都道府県・全50等級で一致することを確かめています。1つでも合わなければ、データを作らずに止まります。
  - 国税庁の源泉徴収税額表（月額表、日額表の丙欄、賞与に対する源泉徴収税額の算出率の表。Excel）
  - 国税庁の月額表の甲欄の電算機計算の特例（PDF）：表が切れ目なく並んでいることと、PDF の計算例の税額と同じになることを確かめています（計算例は、月額表で計算した税額もテストしています）。月額表の行の真ん中の金額で、式と月額表がほとんど10円以内で合うこともテストして、Excel と PDF を照らし合わせています
  - 厚生労働省の雇用保険料率（PDF）
  - 国税庁の通勤手当の非課税限度額の資料（令和7年11月の PDF・令和8年4月の Q&A・タックスアンサー No.2585）：令和8年の表が Q&A とタックスアンサーで一致し、令和7年の表が2つの PDF で一致することを確かめています。Q&A の計算例（ケースA〜E）と同じになることもテストしています
- **データには出典のURLを残す。** 元のファイルは [insurance-tables/](insurance-tables/)・[tax-tables/](tax-tables/)・[minimum-wage-tables/](minimum-wage-tables/)・[nencho-tables/](nencho-tables/)・[commute-tables/](commute-tables/) に置いてあり（年末調整の PDF は大きいので、入手元とハッシュだけ）、新しい年度の追加手順もそこに書いています。
- **自動テスト**（`bun test`）で、計算結果を確かめています。

### 計算できる期間

| 種類 | 登録している期間 |
|---|---|
| 健康保険・介護保険・厚生年金（協会けんぽ） | 2020年3月分〜2027年2月分 |
| 雇用保険 | 2020年4月分〜2027年3月分 |
| 子ども・子育て支援金 | 2026年4月分から |
| 源泉所得税 | 2020年〜2027年に支払う給与・賞与 |
| 定額減税 | 令和6年分（2024年） |
| 通勤手当の非課税限度額（マイカー・自転車など） | 令和7年3月以前（改正前の表）・令和7年4月〜・令和8年4月〜（駐車場等の加算） |
| 最低賃金のチェック | 令和元年度〜令和8年度（2019年10月ごろの発効日から。2020年からの給与はすべて比べられる） |

料率は「何年何月分から」で切り替わるので、年度の途中の改定（令和2年9月の厚生年金の上限、令和4年10月の雇用保険料率など）も、その月から反映されます。
登録していない月を計算したときは、いちばん近い料率で計算し、画面に注意を出します。
2020年3月分より前を登録していない理由は、[insurance-tables/README.md](insurance-tables/README.md) に書いています。

## プロジェクト名について
- **Quick**: ローカル動作ならではの素早さ
- **Quality**: 確かな計算精度
- **Quest**: 理想の給与計算環境の追求

## 開発の背景
市場の給与計算ソフトがクラウド・サブスク型に偏る中、個人事業主や小規模事業者にとって、データの自己管理とランニングコストの削減は重要な課題です。
外部サービスに依存せず、自分のPC一台で完結する、シンプルでコントロール可能な給与計算環境を目指し、本ツールを自作しています。

## 開発の目的
- 「自分が作った」と言える成果物をひとつ完成させること
- クラウドに依存しない、安全で自由な給与計算環境の提供

## プロジェクトの特色：AIとの共創
本プロジェクトは、実務家（非プログラマ）が生成AIを「技術アドバイザー」としてフル活用し、設計から実装までを行う**「AI共創型開発」**の実践です。

- **実務知とITの融合**: 給与計算の実務知識を軸に、生成AIの技術支援を受けることで、専門外であったモダンな技術スタックでの開発を実現。
- **文系AI活用の実践**: 既存のソフトを「消費」するだけでなく、生成AIをパートナーに「作る側」へ回ることで、給与計算ロジックの透明性と自由度を自らの手に取り戻す試みです。

## 技術スタック
ローカルでの動作を前提に、AIとの対話を通じて選定した構成です。

- **Runtime**: [Bun](https://bun.sh/) (高速な実行環境)
- **Framework**: [Tauri](https://tauri.app/) (デスクトップアプリ化)
- **Frontend**: React + TypeScript (UI構築)
- **Icons**: Lucide React (軽量で一貫性のあるアイコンライブラリ)
- **Database**: SQLite (ローカルデータ保存)

## データの保存について
会社ごとのデータを、.qp（Q Payroll のメインファイル）という独自の拡張子のファイルで管理しています。

- **メインデータ（.qp）**: 通常の業務で使用する、読み書きできるファイルです。
- **バックアップデータ（.qb）**: 自動で作られるバックアップファイルです。
- **ポータビリティ**: データのバックアップや PC 間での受け渡しを「1つのファイル」として容易に行えます。

会社・従業員のデータを、外部のサーバーに保存することはありません。
インターネットを使うのは、祝日の取り込み（内閣府のCSV）、法人番号からの会社情報の検索（国税庁）、郵便番号からの住所の検索のときだけです。

## 今後の展望：スタンドアロン・アプリへの展開
本プロジェクトは、最終的に **「インストーラーや.exeファイルをダブルクリックするだけで、誰でもすぐに使い始められるデスクトップアプリ」** として配布・運用することを目指しています。

- **環境構築不要**: コマンド操作（Bunのインストール等）を必要とせず、一般的なソフトと同様の直感的な導入を実現します。
- **完全ローカル完結**: ネット環境に依存せず、PCを開けば即座に業務を開始できる「究極の道具感」を追求します。
- **ファイルから開く**: .qp ファイルをダブルクリックするだけで、その会社のデータを開ける操作を実現します。バックアップ（.qb）は、いまはアプリの「開く」で選ぶと、写しの会社ファイル（.qp）を作って開きます（バックアップのファイルは変えません）。

## 動作環境について
本プロジェクトは、macOS 環境での開発・検証を行っています。
Windows / Linux 環境での動作確認は行っていません。

## 開発用に動かす
1. [Bun](https://bun.sh/) と、Tauri に必要なもの（Rust など。[Tauri の案内](https://tauri.app/start/prerequisites/)）を入れておく

2. 依存関係のインストール
   ```bash
   bun install
   ```

3. 開発モードで起動
   ```bash
   bun tauri dev
   ```

4. 自動テストの実行
   ```bash
   bun test
   ```
