# TimeQard 設計メモ（案）

2026-11-07 作成。ユーザーと決めたことと、作り方をまとめた。同じ日にユーザーの OK をもらって作り始めた（作ったものの状況は 9 を見る）。

## 1. TimeQard とは

- 「TimeQard」（読みは「タイムカード」）は、Q の仲間の、打刻だけをするソフト。Q（給与ソフト）の仲間だとわかるように、Card の C を Q にした。
- 事務所の入口などに置いたパソコン1台で、従業員が出勤・退勤などを押す。押した記録は CSV にして、Q の勤怠に取り込む。
- Q とは別のソフトにする。打刻用のパソコンに、給与やマイナンバーを扱う Q を入れないため。
- 置き場所は、Q と同じリポジトリの `timeqard/`。CSV と従業員ファイルの形は1か所（`shared/timeqard/`）で決め、Q と TimeQard の両方がそれを使う。Q の取り込みとずれないようにするため。
- TimeQard は、インターネットにつながなくても動き、記録をどこにも送らない（ブラウザ版（10）も、同じネットワークの中だけでつながり、インターネットには出ない）。
- アイコンは、名前の中の Q を丸い時計に見立てて描く（Q の尾が時計の針）。Q のロゴと同じ、角の丸い四角の形にそろえる。
- 名前は Web で軽く調べただけ（同じ綴りのソフトはなかった。近い名前に「Q-Time」（QTIHR 社）・「QClock」（Quinyx 社）・「QLOCKTWO」（時計）がある）。出す前に、特許庁の J-PlatPat で商標を調べる。

## 2. 決めたこと

| こと | 決めたこと |
|---|---|
| どこで押すか | 入口などに置いた1台で、全員が押す。サーバー（インターネット上の置き場）も、一人ひとりのアカウントもいらない。2026年11月11日に、各自のパソコンのブラウザからも押せるようにすることにした（入口のパソコンの TimeQard がサーバーになる。一人ひとりに ID とパスワード。10） |
| 打刻に使うパソコン | Windows・Mac・Linux（Ubuntu）。10年以上前の古いパソコンで動くようにする（打刻のためにパソコンを買う予算がない会社を考える）。Linux で動くことは特に大事 |
| ほかの人の分を押せないように | QR コードの打刻カードをかざす。カードが手元にないときは、スタッフ ID を入れて押せる（暗証番号はなし）。ID で押した打刻には印を付けて残し、Q に取り込むときに一覧で出す |
| 押し忘れ・押し間違い | TimeQard の打刻は消さずに残す。直すのは、担当者が Q の勤怠の画面で（Q は打刻の時刻と直した時刻を別の欄に持ち、直した時刻を使う）。押した直後（1分以内）なら、本人が TimeQard で取り消せる（取り消したことも残る） |
| 押し忘れの申し出 | 最初の形に入れる。本人が TimeQard で、日・種類（出勤など）・時刻・理由を入れる。Q は取り込むときに一覧で出し、担当者が確かめてから修正の欄に入れる。「休憩を取れなかった」も、時刻なしで申し出られる（2026年11月11日に足した。Q では、その日の「休憩なし」にする） |
| 休憩 | 会社ごとに選ぶ。TimeQard の設定で、休憩のボタンを出すか出さないかを決める。出さない会社のために、Q に「決まった休憩」の設定を足した（5.6） |
| 配り方 | GitHub の公開ページ（Releases）に、Windows・Mac・Linux 用を置く。Q の「TimeQard」の画面に、そのページを開くボタンを付ける。打刻用のパソコンがネットにつながっていなければ、USB メモリで運ぶ |
| 従業員の情報 | Q から「従業員ファイル」を書き出し、TimeQard に読み込む。ソフトそのものには書き込まない（配るソフトの署名が合わなくなり、従業員が変わるたびに作り直すことになるため） |

## 3. 全体の流れ

| 順番 | どこで | すること |
|---|---|---|
| ① | Q | 「TimeQard」の画面から、ダウンロードのページを開いて TimeQard を手に入れ、入口のパソコンに入れる |
| ② | Q | 打刻カード（QR コード）を印刷して、従業員に配る |
| ③ | Q → TimeQard | 従業員ファイルを書き出し、USB メモリで運んで TimeQard に読み込む（最初と、入社・退職・カードの作り直しのとき） |
| ④ | TimeQard | 毎日、従業員がカードをかざして（または ID を入れて）押す。押し忘れは、その場で申し出る |
| ⑤ | TimeQard → Q | 締めのあと、打刻を CSV に書き出し、USB メモリで運ぶ |
| ⑥ | Q | 勤怠の「CSV 取り込み」で取り込む（会社の印・知らない ID・申し出などを確かめてから入れる） |
| ⑦ | Q | 担当者が確かめて直し、確定する。そのあと給与計算 |

## 4. TimeQard（入口のパソコン）

### 4.1 打刻の画面（いつも出している画面）

- いちばん上に「○○株式会社・11月7日の一覧」（従業員ファイルの会社名と、書き出した日）と、いまの日時を大きく出す。
- 「カードをかざしてください」と出し、カメラの映像を出す。USB の QR コード読み取り機でも、パソコンのカメラでも読める（6 を見る）。
- 「ID で押す」を押すと、ID を入れられる（画面の数字のボタンか、キーボード。文字を入れる欄を使わずキーの位置で読むので、日本語入力がオンでも全角やかなにならない）。入れたら「山田 太郎さん（ID 1001）ですか？」と出して、合っているか確かめる。全角・小文字で入っても直して探す。
- 人がわかったら、名前と、いまの状態（「出勤前」「出勤中」「休憩中」など）と、押すボタンを出す。いまの状態で押すはずのボタンを大きくする（出勤前なら「出勤」）。ほかのボタンは「そのほか」から押せる。
- 押したら「山田 太郎さん　出勤 8:58 を記録しました」を数秒出し、音で知らせる（音は設定で消せる）。1分のあいだは「取り消す」を押せる。
- 「押し忘れを申し出る」ボタン（4.3）。
- 画面には、ほかの人の名前や打刻を出さない。
- キーボードとマウスだけでも使えるようにする（古いパソコンは、タッチ画面でないことが多い）。
- 休憩のボタン・外出のボタンは、管理の画面で出す・出さないを決める（初めは、休憩は出す・外出は出さない）。
- パソコンを点けたら TimeQard が開き、画面いっぱいに出すようにできる。うっかり閉じないように、閉じるボタンでは管理のパスワードを聞く。
- カードが読めないときは、わけを出す（「この会社のカードではありません」「このカードは使えません。担当者に伝えてください」（作り直す前の古いカード）など）。

### 4.2 打刻の記録

- 押したことは、すべて TimeQard の中に残し、消さない・書き換えない（表のトリガーで、書き換えと削除を止める）。残すのは、だれが・いつ（パソコンの時計で、秒まで）・何を（出勤など）・どうやって（カード／ID）・押したときの会社の印。
- 日時は、パソコンの時計（1970年からのミリ秒）に9時間を足した日本時間にする（パソコンのタイムゾーンの設定が日本でなくても同じになる）。タイムゾーンが日本でなければ、画面で知らせる。
- 取り消したときも、元の打刻は消さず、「取り消した」という記録を足す。
- 出勤簿やタイムカードなどの労働時間の記録は、保存が要る（労働基準法109条。本則は5年で、143条の経過措置で当分の間は3年。厚生労働省の資料で、タイムカード等の記録がこれに当たるとされている）。TimeQard は記録を消さない。
- 古いパソコンが壊れたときのために、毎日「控え」（記録のファイルの写し）を、決めたフォルダ（USB メモリなど）に作る（SQLite の VACUUM INTO。新しいものから30個を残す）。控えのフォルダを決めていなければ、管理の画面で知らせる。戻し方は README.md に書いた。
- 古いパソコンは、時計の電池が切れていて、電源を抜くと時計が戻ることがある。いまの時刻が、前に押した時刻より前（1分より多く戻ったとき。インターネットの時計に合わせ直して少し戻っただけなら止めない）か、従業員ファイルを書き出した日より前なら、打刻を止めて「パソコンの時計を直してください」と出す。
- 日をまたぐ勤務（夜勤）は、出勤した日の分にする（Q も「退勤が出勤より前なら次の日」として、出勤した日の行で数えている）。決まりは付録 E。24時間を超える勤務は Q に入らないので、「注意」を出す。

### 4.3 押し忘れの申し出

- カードか ID で人がわかったあとに、「押し忘れを申し出る」を押す。
- 入れるもの：日（今日から1か月前まで）・種類（出勤・退勤・休憩始・休憩終・外出・戻り）・時刻・理由（「押し忘れた」「カードを忘れて押せなかった」「押し間違えた」「パソコンが動かなかった」「そのほか」から選び、ひとこと書ける）。
- 押し間違い（たとえば、退勤を早く押してしまった）も、正しい時刻を申し出られる。押した打刻は残り、申し出は別に残る。
- 申し出は、打刻とは別に残す。1分のあいだは本人が取り消せる（取り消しも記録を足す）。
- 「休憩を取れなかった」も申し出られる（時刻・理由はいらない。わけを書ける）。休憩のボタンを出さない会社でも選べる。
  申し出の種類は no_break（`shared/timeqard/kinds.ts` の `REQUEST_KINDS`）。Q では、担当者が選ぶと、その日の「休憩なし」（給与規定グループの決まった休憩を引かない。5.6）にする。
- 押し忘れを本人の申し出で埋めると、本人の申告で時刻を決めることになる。そこで、担当者が確かめてから Q で入れる。厚生労働省の「労働時間の適正な把握のために使用者が講ずべき措置に関するガイドライン」は、始業・終業の時刻をタイムカードなどの客観的な記録を基に確かめることを原則とし、自己申告によるときは、実際と合っているかを確かめるよう求めている。

### 4.4 管理の画面（パスワードつき）

- 最初に起動したとき：管理のパスワードを決め、従業員ファイルを読み込む。
- 従業員ファイルの読み込み直し（4.6）。
- CSV の書き出し（4.5）。期間は「先月」「今月」か、日付で選ぶ。
- 打刻の一覧：日ごと・人ごとに見られる（取り消し・申し出・ID で押した印も）。ここでは直さない（直すのは Q）。
- 設定：休憩・外出のボタン、音、控えのフォルダ、パソコンを点けたら開くか。
- パスワードを忘れたら：Q で書き出した、いま読み込んでいるものより新しい従業員ファイルを読み込むと、決め直せる。

### 4.5 CSV の書き出し（Q に渡す形）

- 1人1日1行。Q のいまの取り込みの見出し（スタッフID・日付・出勤・退勤・休憩始・休憩終・外出・戻り）に、列を足す。Q は見出しの名前で列を探すので、列を足しても、いまの Q のままで読める（足した列は読まない）。
- 足す列：名前・申し出（申出_出勤〜申出_戻り・申出_休憩なし・申出_理由）・カードなし（ID で押した打刻の種類）・注意・会社の印・形式。くわしくは付録 A。
- 1日のまとめ方：出勤は最初の出勤、退勤は最後の退勤、休憩と外出は最初の1組。取り消した打刻は入れない。Q に入らない打刻（2回目の休憩、1日に2回の出勤など）は「注意」に書く（TimeQard の記録には残る）。
- 時刻は「08:58」の形（秒は切り捨てて、分までにする）。日付は「2026-11-07」の形。文字は UTF-8（BOM つき。Excel で開いても化けない）。
- まだ終わっていない勤務は、出勤だけが入る。あとでもう一度書き出して取り込めば、退勤も入る。
- ファイル名は「○○株式会社_打刻_2026-10-21〜2026-11-20.csv」のようにする。
- 同じ期間を何度書き出して取り込んでもよい（Q は、確定していない日の打刻の欄を入れ直すだけで、確定した日は変えない）。

### 4.6 従業員ファイルの読み込み

- 会社の印が、いま読み込んでいるものと違うファイルは、そのままでは読み込まない（ほかの会社のファイルで上書きしないため）。会社ファイルを作り直したときなど、どうしても切り替えるときは、管理のパスワードを入れ、確かめてから切り替える（打刻には押したときの会社の印が残っているので、前の打刻は前の会社の印で書き出せる）。
- いま読み込んでいるものより古いファイルなら、知らせて確かめる。
- 一覧から消えた人の打刻は消さない（CSV にも出る）。
- 入社日より前・退職日より後の日は押せない（退職のときに書き出し直すのを忘れても、退職日の次の日からは押せない）。

## 5. Q の側で作るもの

### 5.1 「TimeQard」の画面

左のメニューの「勤怠・月次給与」の下に、「TimeQard（打刻）」を足す。

1. TimeQard を手に入れる：ダウンロードのページを開くボタンと、OS ごとの入れ方の説明。
2. 打刻カードを作る・印刷する（5.2）。
3. 従業員ファイルを書き出す（5.3）。最後に書き出した日時を出し、そのあとに入社・退職・カードの作り直しがあれば、「書き出し直して、TimeQard に読み込んでください」と知らせる。
4. 打刻を取り込む：勤怠の「CSV 取り込み」と同じもの（どちらからでも使える）。
5. 使い方の流れ（3 の表）。

### 5.2 打刻カード（QR コード）

- Q で印刷する（担当者のパソコンには、プリンターがあることが多いため）。名刺の大きさに、会社名・名前・ID・QR コードを入れる（A4 の名刺用紙に10枚）。
- 従業員ごとに、カードを作った日（まだ作っていなければ「未発行」）を出す。
- QR コードの中身は、スタッフ ID ではなく、Q がカードごとに作る、推測できない番号（カードの番号）。ID を知っていても、カードは作れない。
- 従業員ファイルには、カードの番号そのものではなく「確かめ用の値」（番号から計算した値で、元の番号には戻せない）だけを入れる。従業員ファイルが漏れても、カードは作れない。
- カードをなくしたら、Q で作り直す。新しい従業員ファイルを TimeQard に読み込むと、前のカードは使えなくなる。
- 守りの強さ：カードを貸したり、写真に撮ってコピーしたりすれば、ほかの人でも押せる（紙のタイムカードと同じくらい）。
- QR コードの読み方は2つ：①パソコンのカメラ（ノートパソコンに付いているもの、USB でつなぐカメラ）、②USB の QR コード読み取り機（キーボードのように文字を打ち込む）。

### 5.3 従業員ファイル

- 入れるもの：形式・会社名・会社の印・書き出した日時と、従業員ごとの スタッフID・名前・入社日・退職日・カードの確かめ用の値。
- 入れないもの：給与・マイナンバー・住所・生年月日・電話・家族など。
- 入れる人：書き出した日に在籍している人（退職日が空か、書き出した日から後）と、入社日がこれからの人。
- ファイル名は「○○株式会社_TimeQard従業員_2026-11-07.json」のようにする。
- 名前は個人の情報なので、USB メモリで運んだあとは消すよう、画面で知らせる。

### 5.4 会社の印

- Q が会社ファイルごとに1つ作る、推測できない8文字（例：K7M3QP2X）。最初に従業員ファイルを書き出すときに作り、会社ファイルに残す。
- 従業員ファイル・打刻カード・CSV のすべての行に入る。
- 秘密のものではない。ほかの会社のファイルと取り違えないためのもの（たとえば、いくつかの会社の給与を Q で扱う事務所）。

### 5.5 取り込みの確かめ（勤怠の「CSV 取り込み」に足す）

取り込む前に、まとめを出して確かめてから入れる。

- 会社の印が違えば、取り込まない（「この CSV は ××株式会社 の打刻です」）。印のない CSV（手で作ったもの、ほかのタイムカードのもの）は、いままでどおり取り込める。
- 形式が、Q の知らない新しいものなら取り込まず、Q を新しくするよう知らせる。
- Q の従業員にない ID の行は入れず、その ID を一覧で出す（いまは確かめていないので、途中でエラーになり、その前の行だけが入るおそれがある）。
- 日付・時刻の形を確かめる。Excel で保存し直すと「2026/11/7」「8:58」になることがあり、いまの Q は「8:58」を時刻として読めず、その日の時間を数えられない（時刻は5文字以上の「08:58」の形だけを読む）。直せるものは直して入れ、直せないものは入れずに知らせる。
- 確定した日は上書きしない（いまと同じ）。その件数を出す。
- 「カードなしで押した打刻」と「注意」を一覧で出す。
- 申し出を一覧で出す。「修正の欄に入れる」を押すと、確定していない日の修正の欄（出勤・退勤などの手入力の欄）に入れ、備考に「TimeQard の申し出：退勤 19:00（押し間違えた）」のように書き足す。修正の欄にもう値がある日は入れずに知らせる。確定は、いつもどおり担当者がする。
- 「休憩を取れなかった」の申し出を選ぶと、確定していない日を「休憩なし」にし、備考に「TimeQard の申し出：休憩を取れなかった（来客が続いた）」のように書き足す。もう「休憩なし」の日は入れずに知らせる。
- 取り込みは、全部入るか、何も入らないかのどちらかにする（途中で止まって、半分だけ入ることがないように）。
- 取り込んだこと（ファイル名・会社・期間・件数）を、Q の記録（ログ）に残す。
- 会社の印・打刻カード・最後に書き出した日時は、新しい2つの表（timeqard_settings・timeqard_cards）に残す。表を足すだけなので、会社ファイルの形式の番号（いまは v8）は上げずにすんだ（開くたびに表を作るので、前の会社ファイルにもそのまま足される。前の Q でも開ける）。

### 5.6 決まった休憩（2026年11月11日に Q に入れた）

TimeQard で休憩を押さない会社などのために、Q に「決まった休憩」を足した（`src/utils/fixedBreak.ts`）。前の Q は、休憩の時刻が入っていない日を「休憩なし」として数えていた。

- 給与規定グループごとに、時刻（「12:00〜13:00」）か長さ（「出勤から退勤までが6時間を超えたら45分、8時間を超えたら60分」）で決め、休憩の時刻が入っていない日に、勤怠を確定するときに引く。従業員ごとに使わないようにもできる。
- その日の記録が先：休憩の時刻を入れた日（手入力・TimeQard の打刻）はその時刻を使い、「休憩なし」にした日は引かない。だから、休憩のボタンを出している会社でも、いつもと違う日だけ押す使い方ができる。
- 休憩を取れなかった日は、本人が TimeQard で「休憩を取れなかった」を申し出（4.3）、担当者が Q の取り込みで選ぶと「休憩なし」になる。

## 6. 作り方（技術）

- Q と同じ Tauri 2 + React + TypeScript + SQLite で、Bun を使って作る。
- 動く OS の目安：
  - Windows 10・11。Windows 7・8.1 では動かない（作るための道具の Rust が、1.78 から Windows 10 より前を外したため）。Windows 10 は Microsoft のサポートが2025年10月に終わっているが、TimeQard は動く。Windows 11 にできない古いパソコンは、Ubuntu を入れて使うこともできる。
  - macOS 10.15（Catalina）以上。古い Intel の Mac 用も作る。
  - Ubuntu 22.04 以上が目安（Tauri 2 が使う WebKitGTK 4.1 が要る。作るときに確かめる）。メモリの少ないパソコンなら、軽い Ubuntu の仲間（Lubuntu など）。
- 古いパソコンのために、画面は軽くする（動きの多い飾りを使わない）。Linux では、パソコンによって画面が白くなることがあるので、その手当て（WebKitGTK の描き方の設定）を入れて確かめる。
- カメラ：画面の側でカメラの映像を受け取り（getUserMedia）、QR コードを読む部品 jsQR（npm の jsqr 1.4.0・Apache-2.0。2026-11-07 にユーザーの許しを得て入れた）で読む。1秒に5回くらい、1こまを横480画素まで小さくして、別の仕事（Web Worker）で探す（動かせない画面の部品なら、画面の側で1秒に2回くらい）。同じカードは、いったん離して3秒たつまで受け取らない。カメラの許可は、Mac は wry が許し（Info.plist にカメラを使うわけを書き、配るものの署名に camera のエンタイトルメントを付ける）、Windows は WebView2 が初めて使うときに聞く。Linux の WebKitGTK は、カメラを使う設定（enable-media-stream）が初めは切ってあり、許可の問い合わせにも答えないので、Rust の側で設定をオンにして、カメラの問い合わせを許す（Mac では組み立てられないので、GitHub の Ubuntu で組み立てるときに確かめる）。古いパソコンのカメラで読めるかは、実際のパソコンで確かめる。
- USB の QR コード読み取り機：キーボードと同じように文字を打ち込む。日本語入力がオンのままでも読めるように、打ち込まれた文字ではなく、キーの位置で読む。QR コードの中身は英大文字と数字だけにする（記号は、キーボードの種類によって化けることがあるため）。
- 記録は SQLite の1つのファイル。打刻・取り消し・申し出は、足すだけにする。
- 配り方：GitHub Actions で、Windows（インストーラーの .exe）・Mac（.dmg）・Linux（.deb と .AppImage）を作り、GitHub の Releases に置く。同じ仕組みで、あとで Q のインストーラーも作れる。
- 署名：最初は署名しない。Windows・Mac では、入れるときに警告が出るので、入れ方の説明に手順を書く（Linux では出ない）。署名の費用（Apple の年会費、Windows の証明書）は、あとで決める。
- 自動の更新は、最初の形では作らない。新しい版は、ページから入れ直す（打刻の記録は残る）。
- Q と同じ部品（React・Tauri など）は、Q のために入っているものを使う。新しく足す部品（QR コードを作る・読む部品、カメラの部品）は、足すときに名前・出どころ・大きさを伝えて、許しをもらう。

## 10. ブラウザ版（各自のパソコンから押す）

2026年11月11日に、ユーザーと相談して決めた。11月12日に第1段階（10.2〜10.4）を作った。有給の申請（10.6）は、まだ設計中。

ユーザーの考えは、Q にサーバーを持たせ、同じネットワークの中のパソコンのブラウザから押せるようにすること。相談して、**サーバーは Q ではなく、TimeQard（入口のパソコン）に持たせる**ことにした。

### 10.1 サーバーを TimeQard に持たせるわけ

- Q を開いていないと押せない形にしないため。入口のパソコンは、勤務の時間中ずっと点いている。
- 給与・マイナンバーの入った Q のパソコンに、ネットワークから入る口を開けないため。入口のパソコンにあるのは、打刻と名前・スタッフID だけ。
  個人情報保護委員会「特定個人情報の適正な取扱いに関するガイドライン（事業者編）」の安全管理措置（技術的安全管理措置）は、外部からの不正アクセス等の防止を求めている。
- Q は一度に1つの会社ファイルしか開かないので、会社ファイルを切り替えても、打刻の先が変わらないようにするため。

### 10.2 決めたこと

| こと | 決めたこと |
|---|---|
| ブラウザでできること | 勤怠の時間のことは、できるだけ全部。出勤・退勤・休憩始・休憩終・外出・戻り（管理の画面で出すことにしたボタン）、押した直後（1分以内）の取り消し、押し忘れの申し出（「休憩を取れなかった」も）、自分の打刻と申し出の一覧 |
| ログイン | 毎回、スタッフID とパスワードを入れる。押したら（または、しばらく何もしなければ）ログアウトする。ログインしたままにはしない |
| はじめのパスワード | 管理者が人ごとに決めて、紙か画面で本人に渡す。人ごとにばらばらにする（全員同じだと、本人がまだログインしていない間に、ほかの人が先に入れてしまう。スタッフID と同じにするのも、同じ理由でしない）。初回ログインで、本人が自分のパスワードに変えるまで、打刻はできない |
| つなげる場所 | 入口のパソコンと同じネットワークの中からだけ。インターネットには出ない |
| 暗号化 | https にする。TimeQard が「会社専用の証明書」（その会社だけの認証局）を自動で作り、各自のパソコンに1回だけ入れる（TimeQard のページからダウンロードして、案内どおりに「信頼する」を選ぶ）。ブラウザで暗号化できるのは https だけで、https には証明書が要る（ブラウザの暗号の部品も、https のページでしか使えない）。証明書を入れずに https にすると、毎回注意の画面が出て、本当に危ないときの注意にも慣れてしまうので、しない |
| Q への渡し方 | 管理の画面から CSV をダウンロードして、Q の取り込みで入れる。USB メモリで運ぶ方法も残す |
| 入口のパソコン | カード・ID・カメラで押すのは、いままでどおり。どこで押したか（カード・ID・ブラウザ）の印を残す |

### 10.3 作ったときに決めたこと（11月11日のおすすめのとおり）

- はじめのパスワード：管理の画面（入口のパソコン・ブラウザの両方）の「はじめのパスワードを作る」で、ばらばらな8文字を作る（見まちがえやすい l・o・0・1 を除いた、小文字と数字の 32 文字。数字と英字の両方を入れる）。
  入口のパソコンの管理の画面では、管理者が自分で決めて入れることもできるが、スタッフID と同じもの・ほかの人の（まだ使える）はじめのパスワードと同じもの・従業員のパスワードの決まりに合わないものは使えない。
  渡すための紙（会社・名前・スタッフID・はじめのパスワード・期限・ブラウザで開くアドレス・使い方）を印刷できる。期限は7日（過ぎたら、管理者が作り直す）。TimeQard にはパスワードを残さないので、紙の画面を閉じると、二度と出せない。
- パスワードの決まり（`src/passwordRules.ts`）：8文字以上・64文字まで。スタッフID と同じもの・同じ文字ばかり（使う文字が2種類以下）・「12345678」「abcdefgh」のような並び・初めと終わりの空白は使えない。
  全角で入れても半角と同じに扱う（日本語入力がオンのまま入れても、ログインできるように）。前と同じパスワードには変えられない。自分で変えるときは、いまのパスワードを確かめる。
- まちがえたとき：5回続けてまちがえたら、15分は使えない（人ごと。正しいパスワードでも入れない）。1台のパソコン（アドレス）から、15分のうちに20回まちがえたら、そのパソコンからのログインを15分止める（何人分も試せないように）。
  ブラウザの管理の画面も、5回続けてまちがえたら15分は入れない（入口のパソコンの管理の画面は使える）。
- ログインの長さ：押したら、すぐにログアウトにする。取り消しは、押してから1分だけ使える札（ログインとは別の、ばらばらな値）でする。何もしなければ、5分でログアウトにする。
  ログインの印は、入口のパソコンの画面の中（メモリ）とブラウザの画面の中にだけ持ち、クッキーやブラウザの保存場所には残さない（ページを開き直すとログアウト）。ほかのパソコンから同じ印が来ても使わせない。
  申し出ではログアウトにしない（出勤と退勤の両方を申し出るなど、続けて申し出られるように）。
- 押せないとき：入口のパソコンと同じ決まり（入社日より前・退職日より後・いまの従業員ファイルにいない・入口のパソコンの時計がおかしい）。従業員ファイルから外れた人のパスワードは、読み込んだときに消す。
- ポート：初めは 8443。管理の画面で変えられる（1024〜65535）。始められなかったら（ほかのソフトが使っているなど）、入口のパソコンの打刻の画面と管理の画面に出す。
- 時刻：ブラウザで押しても、入口のパソコンの時計で記録する（各自のパソコンの時計は使わない。ブラウザの画面にも、入口のパソコンの時刻を出す）。本人が時刻を選べるのは申し出だけで、担当者が確かめてから Q に入れる（厚生労働省「労働時間の適正な把握のために使用者が講ずべき措置に関するガイドライン」の、客観的な記録を基にする考え方に近づけるため）。
- どのパソコンから押したか：つないできたパソコンのアドレス（IP アドレス）を、打刻・申し出の記録に残し、管理の画面の「打刻の一覧」に出す。
- ログインの記録：ログイン・まちがい・止めたこと・期限切れ・本人がパスワードを変えた・管理者がはじめのパスワードを作った／消したことを、日時・アドレスつきで残す（足すだけ）。入口のパソコンの管理の画面に、新しいものから30件を出す。
- ブラウザで押した打刻の印：CSV の「ブラウザ」の列（ブラウザで押した打刻の種類。付録 A）。Q の取り込みのまとめに「ブラウザで押した打刻」として、カードなしの打刻と同じように出す。
- 入口のパソコンのアドレス：ルーターで固定するよう、入れ方の説明に書いた。名前（例：timeqard.local）でもつながるかは、パソコンによって違うので、まだ確かめていない（証明書には、いまは IP アドレスと localhost だけを入れている）。
- スマホ：まずはパソコンだけ（7）。画面は、スマホの幅でも崩れないようにしてある。

### 10.4 作り方（技術）

- サーバー（`src-tauri/src/web.rs`）：hyper（http/1.1）と rustls（暗号の部品は ring）で、0.0.0.0 のポートで受ける。社内のアドレス（プライベートアドレス・リンクローカル）と、このパソコンからのつながりだけを受ける。
  2026年11月12日に、ユーザーの許しを得て、rcgen・pem・yasna・httpdate を crates.io から足した（rustls・tokio-rustls・ring などは、Mac にあったもの）。
- 会社専用の証明書：rcgen で、その会社だけの認証局（20年）を作り、設定のフォルダの `web/` に残す。名前の制約（社内のアドレス・localhost・.local だけ）を付けるので、万が一この鍵が盗まれても、インターネットのほかのサイトのふりには使えない。
  サーバーの証明書（397日）は、このパソコンのアドレスが変わったとき・期限の30日前に、自動で作り直す（各自のパソコンでの入れ直しはいらない）。指紋（SHA-256・SHA-1）を管理の画面とブラウザの画面に出す。
- ブラウザの頼みの流れ：ブラウザ → `POST /api/<名前>`（JSON）→ Rust のサーバー → 入口のパソコンの画面（イベント `timeqard://web-request`）→ `src/webApi.ts` が決まりどおりに答える → `web_respond` → ブラウザ。
  記録のファイルには、`src/webApi.ts` の決まった口（ログイン・パスワードの変更・状態・打刻・取り消し・申し出・自分の記録・ログアウト・管理のログイン・パスワードの一覧・作る・消す・CSV）からしか触らせない。
- ブラウザの画面（`web.html`・`src/web/`）：React で作り、Tauri の部品は使わない。TimeQard に入っている画面のファイルから、サーバーが出す（決まり：ほかのサイトから読み込まない・枠に入れさせない・覚えさせない）。
- ほかのサイトのページからの頼み（なりすましの頼み。CSRF）を断る：`/api/…` は、中身の種類が JSON のものだけを受け、ブラウザが付ける Origin があれば、このサーバーのページ（https://＋Host）からのものだけを受ける。ログインの印はクッキーに入れない。
- パスワードの確かめ（Argon2）は、入口の打刻の画面を止めないよう、別のスレッドで計算する。
- 記録の表（付録 D）：web_accounts（従業員のパスワード）・web_logins（ログインの記録）を足し、打刻・申し出の「どうやって」に web を、つないできたパソコンのアドレスの列を足した。記録のファイルの形の番号は 2。
  Q も TimeQard もまだ作成中なので、前の形（1）の記録のファイルは読まずに、作り直してもらう（TimeQard 0.1.0 で作った記録のファイルは使えない）。
- 共通の形（`shared/timeqard/`）：CSV の「ブラウザ」の列と、打刻の印の種類（card / id / web）。CSV の形式の番号は 1 のまま（まだ作成中のため）。

### 10.5 確かめが要ること

- 証明書の入れ方（Windows・Mac の Chrome・Edge・Safari。Firefox は、別の手順が要ることがある）。手順は、ブラウザの画面（「このパソコンに、会社専用の証明書を入れる」）に書いたが、本物のパソコンでは、まだ試していない。
- 名前の制約の付いた会社専用の証明書を、各ブラウザが受け付けるか（rustls の確かめでは通る。Chrome・Edge・Safari・Firefox では、まだ試していない）。
- ファイアウォールの許可（Windows・Mac・Ubuntu で、はじめに聞かれる）。
- Wi-Fi に「つないだ機器どうしを見えなくする設定」（AP アイソレーション。来客用の Wi-Fi に多い）があると、つながらない。
- 古いパソコンで、サーバーを動かしても、入口の打刻の画面が重くならないか。
- 入口のパソコンが止まっているときは、ブラウザからも押せない（勤務の時間中は点けておく。押せなかった分は、押し忘れの申し出で直す）。

### 10.6 第2段階：有給の申請と、自分の有給（設計中）

ブラウザで押せるようにしたあと（第1段階）に作る。ユーザーの考えは、勤怠の時間のことは、できるだけブラウザでできるようにしたい、というもの。
有給を申請するには、自分の有給があと何日あるかもわからないといけない。

打刻は TimeQard から Q への一方通行ですむが、有給の申請は、本人の申請（TimeQard）→ 担当者の受け付け（Q）→ 結果と残りを本人へ（Q から TimeQard）と、行って帰る流れが要る。

本人がブラウザでできること（ログインしてから、本人の分だけ）：

- 自分の有給を見る
  - いまの残り（「9日と5時間」のように。Q の有給の画面と同じ数え方）
  - 付与ごとの内訳：付与日・付与した日数・使った日数・有効期限・期限で消える日数（期限が近い付与を目立たせる）
  - 取った日（日・全休／半休／時間）
  - 申請中の日と、申請中の分を引いた残りの見込み
  - いつの時点の数え方か（Q で従業員ファイルを書き出した日の、確定した勤怠まで）
  - 年5日の取得の進み（年10日以上付与された人。Q で年5日の数え方を作ってから出す）
- 有給を申請する：日・全休／半休（午前・午後）／時間単位（会社が半日単位・時間単位を認めているときだけ出す）・ひとこと。申請中の分も引いた残りより多くは申請できない。
- 申請を取り下げる（担当者が受け付ける前なら）。
- 返事を見る：「受け付けた」か「日を変えてほしい（わけ）」。

担当者（Q）がすること：

- 打刻の CSV と一緒に申請を取り込み、取り込みのまとめに一覧で出す。
- 受け付けると、その日の勤怠に「全休(有給)」「半休(有給)」「時間有給（時間）」を入れる（確定は、いつもどおり担当者がする）。
  有給の残りは、いまの Q の数え方（確定した勤怠から数える。`src/utils/paidLeave.ts`）がそのまま使える。
- 日を変えてほしいときは、わけを書いて返す。会社が日をずらしてもらえるのは、事業の正常な運営を妨げるときだけ（労働基準法39条5項ただし書き。時季変更権）。
  そのため、返事は「却下」ではなく、「受け付けた」か「日を変えてほしい」の二つにする。

Q から TimeQard へ戻すもの（従業員ファイルに足す）：

- 人ごとの有給のまとめ（時点・残り・付与ごとの内訳・取った日）と、申請への返事。
- ブラウザの管理の画面から、従業員ファイルを読み込めるようにする（USB メモリで運ぶ方法も、いままでどおり残す）。
- 従業員ファイルに給与・マイナンバー・住所を入れない決まりは、そのまま。足すのは、有給の日数と申請への返事だけ。

見せる場所：

- 本人がブラウザでログインしたとき（本人の分だけ）と、管理の画面（全員分）。
- 入口のパソコンの打刻の画面（カードをかざしたとき）には出さない（後ろに並んでいる人に見えるため）。

法律の確かめ：

- 年次有給休暇は、本人が時季を指定して取る（労働基準法39条5項）。
- 年10日以上の有給が付与される人には、会社が、付与日から1年のうちに5日を、時季を指定して取らせる（同条7項。本人が取った日・計画的付与の日は、その分を引ける）。
- 時間単位の有給は、労使協定を結んだときだけ、年5日分まで（同条4項）。
- 半日単位は、本人が望み、会社が同意したときに与えられる（会社の決まりで、出すかどうかを決める）。
- 年次有給休暇管理簿（時季・日数・基準日。労働基準法施行規則24条の7）は、Q の有給の画面で見られる。申請の記録も残る。

まだ決めていないこと（おすすめ）：

- 申請の締め切り（例：前の日まで）は、会社の決まり（就業規則）に合わせて、管理の画面で決める（初めは決めない）。
- 当日の朝の申請（急な病気など）も申請として受け、担当者が確かめる。
- Q の年5日の数え方（付与日から1年のうちに取った日数と、あと何日要るか）は、Q の有給の画面にも要るので、先に Q で作る。

## 付録（作る人向けの形の案）

### A. CSV

列の順番（この順で書く。Q は見出しの名前で読む）：

```
スタッフID,名前,日付,出勤,退勤,休憩始,休憩終,外出,戻り,申出_出勤,申出_退勤,申出_休憩始,申出_休憩終,申出_外出,申出_戻り,申出_休憩なし,申出_理由,カードなし,ブラウザ,注意,会社の印,形式
```

例（`shared/timeqard/csv.ts` の writeTimeQardCsv で作ったもの）：

```
1001,山田 太郎,2026-11-04,08:58,18:02,12:00,13:00,,,,,,,,,,,,,,K7M3QP2X,TimeQard 1
1002,佐藤 花子,2026-11-04,,17:31,,,,,09:00,,,,,,,出勤：押し忘れた,退勤,,出勤がありません,K7M3QP2X,TimeQard 1
1003,鈴木 一郎,2026-11-04,22:00,06:05,02:00,02:45,,,,,,,,,,,,,,K7M3QP2X,TimeQard 1
1004,高橋 次郎,2026-11-04,09:00,18:00,,,,,,,,,,,○,休憩なし：休憩を取れなかった（来客が続いた）,,,,K7M3QP2X,TimeQard 1
1005,伊藤 三郎,2026-11-04,08:55,17:40,,,,,,,,,,,,,,出勤 退勤,,K7M3QP2X,TimeQard 1
```

- 1002 は、出勤を押し忘れて「9時に出勤した」と申し出、退勤は ID で押した日。
- 1003 は夜勤。6:05 の退勤は、出勤した 11月4日の行に入る。
- 1004 は、休憩を取れなかったと申し出た日（申出_休憩なし に「○」）。
- 1005 は、自分のパソコンのブラウザで出勤・退勤を押した日。
- カードなし：ID で押した打刻の種類を、空白で区切る（例「出勤 退勤」）。
- ブラウザ：ブラウザで押した打刻の種類を、空白で区切る（例「出勤 退勤」。10）。
- 注意：いくつかあるときは「／」で区切る。
- 申出_理由：「種類：理由（ひとこと）」を「／」で区切る（例「出勤：押し忘れた／退勤：押し間違えた（会議が長引いた）」）。Q は、修正の欄に入れるときに、その種類の理由を備考に書く。
- 名前・申出_理由・注意は、改行と「,」「"」を空白に置き換える（いまの Q の読み方でも崩れないように）。共通の形には、引用符を正しく扱う CSV の読み方を作り、Q の取り込みもそれを使う。
- 申出_休憩なし：「休憩を取れなかった」の申し出があれば「○」。
- 形式：「TimeQard 1」。形を変えたら番号を上げる。Q は、知っている番号までの CSV を取り込み、新しい番号なら Q を新しくするよう知らせる。

### B. 従業員ファイル（JSON）

```json
{
  "format": "timeqard-staff",
  "version": 1,
  "companyName": "○○株式会社",
  "companyMark": "K7M3QP2X",
  "exportedAt": "2026-11-07T16:30:00+09:00",
  "staff": [
    {
      "id": "1001",
      "name": "山田 太郎",
      "joinDate": "2019-04-01",
      "retirementDate": null,
      "cardHashes": ["（64けたの確かめ用の値）"]
    }
  ]
}
```

### C. QR コードの中身

- 「TQ1」＋会社の印（8文字）＋カードの番号（26文字）＝37文字。文字は A〜Z と 2〜7 だけ（Base32）。QR コードの英数字だけの形で入るので、小さな QR コードですむ。
- カードの番号は、でたらめな 128 ビット。確かめ用の値は、カードの番号の SHA-256。
- Q はカードの番号を会社ファイルに残す（同じカードを刷り直せるように）。作り直すと、前の番号は使えなくなる。

### D. TimeQard の中の表（SQLite）

- punches（打刻）：番号・スタッフID・種類（entry / exit / break_start / break_end / out / return。Q の列の名前に合わせる）・押した日時（秒まで、+09:00 つき）・どうやって（card / id / web）・つないできたパソコンのアドレス（web のとき）・会社の印
- cancellations（取り消し）：取り消した打刻（または申し出）の番号・取り消した日時
- requests（申し出）：番号・スタッフID・日・種類（打刻の6種類と、no_break（休憩を取れなかった））・時刻（no_break は空）・理由・ひとこと・申し出た日時・どうやって・つないできたパソコンのアドレス・会社の印
- web_accounts（ブラウザ版の従業員のパスワード）：会社の印・スタッフID・確かめ用の値（Argon2）・はじめのパスワードか・その期限・続けてまちがえた回数・使えない期限・変えた日時
- web_logins（ログインの記録。足すだけ）：会社の印・スタッフID（管理者は「(管理者)」）・こと（ok / wrong / locked / expired / no_account / ip_blocked / changed / issued / cleared）・アドレス・日時
- staff（従業員ファイルの中身。読み込み直すと入れ替える。一覧から消えた人も、名前は CSV のために残す）
- settings（管理のパスワードの確かめ用の値・ボタン・音・控えのフォルダ・ブラウザ版を使うか・ポート・ブラウザの管理の画面のまちがいの回数など）
- 記録のファイルの印（application_id）は「TQ01」、形の番号（user_version）は 2。
- exports（書き出した期間・ファイル名・日時）
- 1日の行（出勤・退勤…）は、記録から毎回計算し、表には残さない（まとめ方を変えても、記録はそのまま）。

### E. 1日のまとめ方の決まり

- 出勤を押すと、新しい勤務が始まる。勤務の日は、出勤を押した日。
- 退勤・休憩始・休憩終・外出・戻りは、24時間のうちに始まった、まだ退勤していない、いちばん新しい勤務の分。そういう勤務がなければ、押した日の分にして「出勤がありません」と注意を出す。
- 同じ日に2つ目の勤務があれば、1つ目を Q に渡し、「1日に2回出勤しています」と注意を出す。
- 退勤のない勤務は「退勤がありません」と注意を出す（出勤から24時間たっていなければ出さない。次の日の出勤があれば、すぐ出す）。
- 退勤していない同じ日の勤務があるときの出勤は、押し直しとして、初めの出勤を使う（「出勤を2回押しています」）。
- 退勤のあと3時間のうちにもう一度退勤を押したら、同じ勤務の後の退勤を使う（「退勤を2回押しています」）。3時間を超えた退勤は、押した日の行にする（夜勤の次の日に出勤を押し忘れたときに、前の日の勤務に入れないため）。
- 休憩・外出は最初の1組を入れる。10分のうちに同じボタンを2回押したら、押し直しとして1回にする。2組目は「2回目の休憩（15:00〜15:10）は Q に入りません」と注意を出す。
- 退勤のあとに押した休憩などは、行に入れずに注意を出す。
- 書き出すときは、期間の前の日と次の日の打刻も読んでから、期間の行だけを出す（期間をまたぐ夜勤を正しくまとめるため）。
