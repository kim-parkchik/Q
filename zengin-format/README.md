# 振込データ（全銀協規定形式）の元データ

Q の振込データ（給与振込・賞与振込。`src/utils/zengin.ts`）で使うレコードの形（各項目の名前・数字か文字か・バイト数、データ区分・種別コード・預金種目などの値、名前に使える記号）は、
銀行が公開している仕様書の PDF から、スクリプトで読み取って `src/constants/zengin.ts` に作っています（手で書き写していません）。

## データの作り方

追加のインストールは要りません（Python の標準ライブラリと、macOS の PDFKit（`scripts/pdf_to_text.swift`）だけで動きます）。

```
python3 -I scripts/import_zengin_format.py \
    zengin-format/source/mufg/form_4_1_2_20080512.pdf \
    zengin-format/source/jp-bank/dataform_kyuyo.pdf \
    src/constants/zengin.ts
```

スクリプトは、次のときにファイルを作らずに止まります。

- どちらかの仕様書で、各レコード（ヘッダー・データ・トレーラー・エンド）のバイト数の合計が120でない、項番や位置が続いていない
- 三菱UFJ銀行の項目のバイト数と、ゆうちょ銀行の桁数が違う（ゆうちょ銀行は、終わりのダミーを処理結果の欄などに分けているので、そこは合計で比べる）
- 決まった値を入れる項目（ゆうちょ銀行の条件が ○・△ の項目）で、数字か文字かが違う
- データ区分・種別コード・預金種目・新規コード・許容記号が読めない、1つに決められない

数字を1か所ずつ変えた5通り（ヘッダーの会社名のバイト数・データの口座番号の属性・トレーラーのダミーの長さ・ゆうちょ銀行の振込金額の桁数・データの最後がダミーでない）で、全部止まることを確かめました。

## 銀行ごとの違い

全銀協規定形式はどの銀行でも同じ形ですが、受け付ける文字や任意の項目の扱いは銀行ごとに少し違います。

- 名前（委託者名・金融機関名・支店名・口座名義）に使える記号は、両方の銀行で使えるもの（`( ) - / , .`）だけにしています。
- 改行の有無（レコード長120か、改行ありか）は、振込データの画面で選びます（クラウド型の給与ソフトと同じく、初めは120（改行なし））。
- 銀行によっては、ゆうちょ銀行の振替口座のように、口座番号の書き方が違うことがあります。振込データを送る前に、使う銀行の仕様書を確かめてください。
